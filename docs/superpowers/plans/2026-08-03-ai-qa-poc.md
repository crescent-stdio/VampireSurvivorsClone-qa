# AI Gameplay QA PoC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Follow strict red-green-refactor TDD for runtime behavior.

**Goal:** Add a deterministic, local-only automated gameplay QA harness with a scripted baseline and Unity ML-Agents integration while preserving the original game flow.

**Architecture:** A QA-only scene bootstraps deterministic episodes around the existing Level 1 composition root. A controller exposes fixed observations and actions, independent oracles record failures, and interchangeable scripted or ML-Agents drivers consume the same contracts. Original gameplay defaults remain unchanged.

**Tech Stack:** Unity 6000.0.80f1, C#, Unity Test Framework, Unity ML-Agents Release 23 (`com.unity.ml-agents` 4.0.0 and Python packages 1.1.0), Python 3.10.12 and PyTorch 2.8.0 managed by uv 0.12, POSIX shell.

## Global Constraints

- Keep Unity at `6000.0.80f1` and ML-Agents at Release 23 after the compatibility migration.
- Keep external model integration opt-in and isolated to the QA lane. Never expose secrets or block the Unity LLAPI loop on network calls.
- Preserve all existing API names and parameters; only additive public observability/test seams are allowed.
- Keep the original `Level 1` scene and blueprint behavior unchanged; QA behavior belongs to dedicated QA assets.
- Code comments and repository documentation must be English; user-facing reports remain Korean.
- Use `Random.InitState(seed)` and record every action; do not abstract all physics, time, or randomness in this PoC.
- Runtime artifacts must stay untracked.
- Use strict TDD for production behavior and do not weaken existing or new tests.

### Task 1: Compilation and test boundaries

Create `Vampire.Runtime.asmdef` under `Assets/Scripts` with explicit references required by Input System, Localization, TextMesh Pro, and ML-Agents. Add EditMode and PlayMode test assemblies under `Assets/Tests`. Pin ML-Agents Release 23 and verify that existing scenes and prefabs retain script GUID connections after recompilation.

Acceptance: the project compiles in Unity 6000.0.80f1; an intentionally failing smoke test is observed before the minimal passing runtime contract is added; both test assemblies are discoverable.

### Task 2: QA contracts, deterministic scripted policy, and result model

Test-first add `QaEpisodeOutcome`, `QaAction`, `QaObservation`, `QaEpisodeResult`, `IQaPolicy`, and `ScriptedQaPolicy` under `Assets/Scripts/QA`. The action contract is normalized movement plus ability choice `-1` or `0..3`. Observations include player state, up to eight nearest enemies, up to four ability choices, level phase, statistics, and modal state. The scripted policy retreats from immediate danger, otherwise approaches the nearest collectible/chest, and selects abilities through a stable priority order.

Acceptance: EditMode tests cover normalization, fixed-size observation defaults, deterministic decisions, danger retreat, target approach, ability priority, result serialization, and invalid choice handling.

### Task 3: Additive gameplay observability and selection seams

Test-first add read-only character health/experience/alive properties, LevelManager initialized/time/outcome properties, EntityManager read-only chest/entity counts, and AbilitySelectionDialog displayed-option access plus `TrySelectOption(int)` and a default-true `PauseOnOpen`. Ensure normal gameplay behavior is unchanged. Add explicit, single-assignment terminal outcome handling so simultaneous pass/fail cannot grant rewards twice.

Acceptance: EditMode/PlayMode tests demonstrate unchanged default pause behavior, QA non-pausing mode, valid/invalid selection, initialization state, and exactly-once terminal transitions.

### Task 4: Episode controller, telemetry, replay, and oracles

Test-first add an early-execution `QaEpisodeController` that seeds random state before gameplay initialization, supplies the QA character, applies 10 Hz actions, captures fixed observations, reloads the QA scene between episodes, and writes JSONL action/telemetry plus a summary JSON. Capture Unity errors/asserts/exceptions, NaN/Infinity, unknown `timeScale == 0`, stalled game time, modal timeout, and duplicate terminal events. Snapshot and restore `PlayerPrefs["Coins"]` even when an episode ends abnormally where possible.

Acceptance: tests cover seed propagation, action acknowledgement, observation cadence, each oracle, one terminal result, artifact shape, and PlayerPrefs restoration. A five-run replay contract compares outcome and discrete random events exactly and positions within `0.05` units.

### Task 5: ML-Agents adapter and training configuration

Test-first add `QaGameplayAgent : Agent` as an adapter over the controller contracts. Use two continuous movement actions and one five-value discrete ability branch. Collect only fixed vector observations. Apply rewards: pass `+10`, death/error `-2`, level-up `+0.1`, kill `+0.01`, new state bucket `+0.02`, normalized damage penalty, and a stalled-progress penalty. Add Release 23 PPO training YAML and deterministic inference/evaluation configuration.

Acceptance: EditMode tests validate observation count/order, action mapping, reward deltas, state-bucket stability, and episode termination. The adapter must not contain gameplay rules duplicated from the controller.

### Task 6: Dedicated QA assets and generic commands

Create a QA-only level blueprint and scene. Preserve the original spawn/chest proportions while setting miniboss at 45 seconds and final boss at 90 seconds. Use an early QA bootstrap to populate `CrossSceneData` before `Character.Awake`, disable ability-menu pausing only in the QA lane, and include the QA scene after the existing build indices 0 and 1. Add provider-independent shell commands for setup, training, evaluation, replay, Unity EditMode tests, and Unity PlayMode tests. Add English operator documentation and ignore generated builds, logs, traces, screenshots, checkpoints, and models.

Acceptance: asset contract tests verify scene order, non-null blueprint/prefab references, 45/90-second timing, spawn-array consistency, loot probability validity, localization completeness, and explicit Addressables build requirements. Scripts fail clearly when Unity 6000.0.80f1, uv 0.12, Python 3.10.12, or the committed lock contract is unavailable.

### 2026 OpenAI QA extension

The later QA extension adds `-qaMode=llm`, an asynchronous OpenAI movement policy, immediate local ability selection, and post-terminal LLM artifacts. The Python environment is unified under `pyproject.toml` and `uv.lock`; PPO remains an optional `trainer` extra. See `docs/qa/AI_AGENT_QA_GUIDE.ko.md` for the current operator contract. This extension does not change the 36-float observation vector, action space, PPO YAML, or scripted smoke/replay behavior.
